## Project notes (latopis-nechrubelski)

Notes the universal standard asks each app to record. Standard entries are in AGENTS.md; this section wins where it says so.

- **Routing mode (STD-007):** React Router **framework mode** (`ssr: true`, prerendered psalm pages, `frontend/react-router.config.ts`). `frontend/app/routes/` holds the route modules and acts as the pages layer's routing shell; the page components themselves live in `components/pages/`.
- **Component levels (STD-003):** `frontend/app/components/{atoms,molecules,organisms,templates,pages}/<Name>/`. Import direction is enforced by `npm run lint` (`no-restricted-imports`); molecules do not import other molecules. Shared component types live in `components/models.ts`.
- **Lint parser (STD-002/003):** ESLint parses TS via `@babel/eslint-parser`, not typescript-eslint, because typescript-eslint rejects TypeScript 7. Type checking stays with `tsc`. Switch back once typescript-eslint supports TS >= 7.1. As a consequence there is no `no-explicit-any` lint rule; STD-005 is a review check.
- **Icons (STD-003):** HeroIcons outline (`@heroicons/react/24/outline`), only behind the `Icon` atom (`components/atoms/Icon/`), so swapping the set is a one-file change. First used by the volume control (speaker / speaker-muted). The share dialog uses `react-share` brand marks and one local Discord brand mark instead, because HeroIcons intentionally has no social brands; do not reuse those as general UI icons.
- **Not used yet (STD-007):** React Hook Form (no forms) and `analytics` (no tracked events). Add them with the first form / first event.
- **Error reporting:** Sentry SDKs -> GlitchTip, one project, events tagged `source: backend|frontend`. Browser events are proxied through the backend's `POST /api/tunnel` (`backend/src/routes/tunnel.ts`, behind CSRF, 60/min per visitor); the tunnel only accepts the project in `GLITCHTIP_DSN` and pins that DSN's key server-side. The frontend transport in `lib/error-reporting.ts` fetches a CSRF token per send. Backend reads `GLITCHTIP_DSN` at runtime; the frontend reads it at build time as `VITE_GLITCHTIP_DSN` (pages are prerendered). The browser bundle only carries a placeholder key (`https://tunnel@…`, derived in `deploy.yaml`); the real key stays server-side. Backend events are redacted in `backend/src/sentry.ts` (auth/cookie/CSRF headers, and the monitor token in `/api/monitor/:token`). **Source maps go to GlitchTip only:** with the DSN + `SENTRY_AUTH_TOKEN`/`SENTRY_PROJECT` set, the client build emits `hidden` maps, `@sentry/vite-plugin` uploads them under release `latopis-nechrubelski@<commit>` and deletes them, the server bundle never gets any, and `npm run check:monitoring` (run inside the Docker build) fails if any `.map` or `sourceMappingURL` remains. A failed upload fails the build (`errorHandler` throws; the plugin only logs by default). The token is a BuildKit secret, never a build arg. Both are no-ops when unset; the tunnel route is only registered when the DSN is set.
- **Rate limiting (STD-001):** `@tackgnol/rpgtools-shared-auth` >= 1.7.2 keys the global limiter and Better Auth's sign-in limit on the real client IP (its exported `clientIp`), so no local `keyGenerator` is needed; `backend/src/server.ts` only sets `max` (300/min per visitor, 10000 under test). `backend/src/rate-limit.test.ts` checks two visitors behind one proxy peer get separate buckets against the real server.
- **React Doctor (STD-009):** baseline before the standard was applied: **79**. Current: **100** (no findings, since the narration build). Floor 80, never regress; enforced by the `react-doctor` step in `.woodpecker/verify.yaml`. No accepted findings.
- **Narration (audio):** played through **Howler.js** (Web Audio mode), which STD-007 has no row for. It is there because Safari always sends `Range` requests and won't serve them from a cached full response, so a `fetch()` prefetch does nothing on iOS; Howler downloads each file whole and caches the decoded buffer, and its `autoUnlock` covers WebKit's gesture rule. `lib/narration.ts` holds the player (`createNarrator`: one voice at a time, next-verse prefetch, a missing file skipped silently) behind a small `Sound` interface a Howl satisfies; `useNarration` in `BookPage` owns it for the page. Recordings are `/audio/<variant>/<psalm>-<verse>.m4a`, served by host Caddy from the VM (`scripts/upload-audio.sh`, never a deploy); `vite dev` proxies `/audio` to prod (`VITE_AUDIO_PROXY_TARGET` overrides). Variant and volume are per-device `localStorage` preferences (`lib/stored.ts`). The yellow ink only marks the verse being read aloud; the roll's verse is ignored by the frontend (the backend still rolls and logs it).
- **Credits:** `CreditsControl` (molecule, top-left "Źródła" torn button opening a popover) holds the narrator ("Czytane przez Tuje Szmaragd"), the text source and the Pixabay art credits. The narrator name and art entries live in `CreditsControl.utils.ts`, the copy in `common.pl.ts`. Add a line there whenever a new image mask or voice is added.
- **Signed-in indicator:** `UserIndicator` (organism) reads shared-auth's `GET /api/me` and shows a torn-paper "Welcome, <nickname>" tag top right, only for non-anonymous users; the nickname is the Logto `preferred_username` (`login`). Nothing in the UI can sign a user in yet (anonymous only, ticket 05), so it stays hidden until Logto is wired. The copy lives in `common.pl.ts` (`welcome`).
